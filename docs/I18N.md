# Interface localization

FloatRead separates **interface language** from **translation language**. Popup, Settings, Onboarding and companion controls support Simplified Chinese and English only (plus browser-auto selection). Page translation supports one to five source languages and one target language; adding a translation language does not add another interface locale.

FloatRead supports Simplified Chinese (`zh_CN`) and English (`en`) for its own interface. Page output uses the separately configured target language.

- Manifest name, description, commands and context-menu labels use Chrome `_locales` resources.
- Runtime interface copy uses the typed catalog in `src/i18n/catalog.ts`.
- The default `auto` setting follows `chrome.i18n.getUILanguage()`; users may explicitly choose Chinese or English in Settings → Reading behavior and language.
- Content Script receives only the resolved public locale through the validated bootstrap message. It never reads private settings or credentials.
- Adding a runtime message requires the same key in both catalogs. TypeScript rejects a missing English key.

Automated coverage verifies both catalogs, an English Popup/onboarding render, localized Content controls and live English/Chinese switching in the real extension settings page.
