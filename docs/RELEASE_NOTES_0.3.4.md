# FloatRead 0.3.4 发布说明

发布日期：2026-07-22

## 这次查到的问题

在实际 X 页面上，扩展已经连接成功，但长时间显示“正在翻译可见页面，已完成 0 处”。现场测量发现：

- 当前屏幕内有 72 个文字节点，但旧扫描还额外包含屏幕下方 280 像素内的 13 个节点。
- 网页内部顺序最前面是隐藏的快捷键提示和左侧菜单，因此第一批不是用户正在看的推文正文。
- Provider 必须完成整批 JSON 后才写入页面，导致已经开始生成时仍长期显示 0。

## 本次修复

- 严格只处理与当前屏幕相交的文字；滚动进入屏幕后再处理新内容。
- 按文字本身的位置判断可见性，并排除裁切、隐藏和仅供辅助阅读器使用的文字。
- 第一批优先翻译正文，菜单和按钮随后处理并继续使用本地缓存。
- Provider 改为流式接收；每得到一条完整、安全校验通过的译文就立即写回，不等待整批结束。
- DeepSeek 流式请求继续记录 Provider 返回的输入和输出 Token。

本轮没有扩大扫描上限，没有恢复字符变化监听，没有自动翻译屏幕外时间线，也没有增加权限、遥测或开发者服务器。

## 更新后测试

1. 在 `chrome://extensions` 重新加载 FloatRead，确认版本为 `0.3.4`。
2. 回到 X，不需要刷新网页，单击宠物。
3. 当前屏幕中的推文正文应先出现译文；菜单随后翻译。
4. 屏幕下方尚未看到的内容不应提前翻译，滚动进入屏幕后才开始处理。
5. 再次单击宠物应立即停止。
